이 페이지는 **Shane’s Athenaeum에서 글을 쓰는 방법을 설명하는 Test 글**입니다. 문법을 보여 주는 코드 상자와 실제 표시 예시를 함께 넣었습니다.

## 글 작성과 수정

1. [글 관리 화면](/admin/)에 로그인합니다.
2. 새 글은 **Create New Entry**, 기존 글 수정은 목록에서 글 제목을 선택합니다.
3. **제목**, **발행일**, **글 종류**, **짧은 소개**를 입력합니다.
4. 본문을 작성하고 **Save**를 누릅니다.
5. 공개하려면 **초안으로 저장**을 끄고 저장합니다. 자동 배포가 끝나면 Blog에 표시됩니다.

**초안으로 저장**을 켜면 블로그에는 표시되지 않습니다. 다만 공개 GitHub 저장소에 원문이 저장되므로 비밀 자료를 보관하는 용도로 쓰지는 않습니다. 미래 발행일을 지정한 글은 해당 날짜 전에는 표시되지 않습니다.

## 블로그 카드 설정

글 관리 화면에서 다음 항목을 입력하면 `Blogs.` 목록에 반영됩니다.

- **메인 이미지**: 카드 상단에 표시합니다. 가로 16:9 이미지를 권장하며, 비워두면 기본 그래픽을 사용합니다. 본문에 넣는 이미지와 별도로 지정합니다.
- **섹션**: `Interpretability/XAI`, `Agent Security`, `Benchmark` 중 하나를 선택합니다. 선택한 필터와 `All`에 표시되며, 비워두면 `All`에만 표시합니다. 이 글쓰기 가이드는 섹션을 비워두었습니다.
- **Description · 짧은 소개**: 카드의 제목 아래에 표시할 설명을 적습니다.
- **메인 키워드**: 날짜 옆에 표시할 핵심어입니다. 예를 들어 `Mechanistic Interpretability`나 `Prompt Injection`을 적을 수 있습니다. 비워두면 섹션 또는 글 종류를 표시합니다.

메인 이미지는 글과 함께 저장됩니다. 이미지를 바꾸거나 섹션을 수정한 뒤에도 **Save**를 눌러야 반영됩니다.

## 서식 편집기와 Markdown 모드

기본 서식 편집기에서는 버튼으로 굵게 쓰기, 기울임, 링크, 이미지, 표를 넣을 수 있습니다. 본문 위의 **Edit in Markdown**을 켜면 원문 문법을 직접 편집할 수 있습니다. 다시 끄면 서식 편집기로 돌아갑니다.

논문 수식이나 코드 블록을 정교하게 작성할 때는 Markdown 모드가 편리합니다. 편집기 미리보기와 실제 블로그의 글꼴·수식 표시는 다를 수 있으니, 발행 후 실제 글도 확인합니다.

## 제목과 문단

글의 큰 제목은 위쪽 **제목** 입력란에 적습니다. 본문의 큰 절은 `##`, 그 안의 작은 절은 `###`로 작성합니다. 이렇게 작성한 소제목은 글의 목차에도 연결됩니다.

```markdown
## 핵심 아이디어

첫 번째 문단입니다.

### 기존 방법과의 차이

두 번째 문단입니다.
```

문단 사이는 빈 줄로 나눕니다. 서식 편집기에서는 Enter가 새 문단, Shift+Enter가 문단 안의 줄바꿈입니다.

## 강조, 링크, 인용문

```markdown
**굵게** / *기울임* / `변수 또는 짧은 코드`

[링크에 표시할 이름](https://shanespark.github.io/)

> 인용문이나 별도로 강조할 설명
```

실제 표시: **굵게** / *기울임* / `hidden_states`

[블로그 메인으로 이동](https://shanespark.github.io/)

> 인용문 예시입니다. 논문을 직접 인용할 때는 출처를 함께 적습니다.

## 목록

```markdown
- 첫 번째 항목
- 두 번째 항목

1. 데이터 준비
2. 실험 실행
3. 결과 분석
```

- 첫 번째 항목
- 두 번째 항목

1. 데이터 준비
2. 실험 실행
3. 결과 분석

## 수식 넣기

### 문장 안의 수식

수식 양쪽을 달러 기호 하나씩으로 감쌉니다.

```text
선형 변환은 $h = Wx + b$로 표현합니다.
```

선형 변환은 $h = Wx + b$로 표현합니다.

### 별도 줄의 수식

달러 기호 두 개를 위아래 줄에 쓰고 가운데에 LaTeX 수식을 적습니다. 블록 앞뒤에는 빈 줄을 둡니다.

```text
$$
\operatorname{Attention}(Q,K,V)
=\operatorname{softmax}\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V
$$
```

실제 표시:

$$
\operatorname{Attention}(Q,K,V)
=\operatorname{softmax}\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V
$$

자주 쓰는 문법은 `\frac{a}{b}`(분수), `x_i`(아래 첨자), `x^2`(위 첨자), `\sum_{i=1}^{n}`(합), `\sqrt{x}`(제곱근)입니다. 수식을 실제로 표시하려면 코드 블록 밖에 적습니다.

## 이미지 넣기

### 편집기에서 업로드

1. 본문 위의 **Image** 버튼을 누릅니다.
2. 이미지 입력 상자의 **Browse**를 누르고, 이미지 라이브러리에서 **Upload**로 파일을 올립니다.
3. 이미지를 선택하고 **Insert**를 누릅니다. 이미지 설명에는 그림이 무엇을 뜻하는지 적습니다.
4. 글을 **Save**하면 이미지와 글이 함께 저장됩니다.

서식 편집기에 이미지를 붙여넣거나 드래그해서 넣을 수도 있습니다. 논문의 그림을 사용할 때는 그림 아래에 논문명·Figure 번호·원문 링크를 함께 적습니다.

### Markdown으로 연결

현재 글에 업로드한 파일 이름이 `figure.png`라면 다음처럼 씁니다.

```markdown
![그림의 내용을 설명하는 대체 텍스트](figure.png)

그림 설명과 출처를 여기에 적습니다.
```

대괄호 안은 이미지가 표시되지 않을 때 읽을 설명, 소괄호 안은 파일 경로 또는 이미지 URL입니다. 파일 이름은 실제 업로드된 이름과 같아야 합니다.

## 표 넣기

서식 편집기의 **Insert Table** 버튼으로 표를 만들거나, Markdown 모드에서 아래처럼 작성합니다. 두 번째 줄은 제목 행과 본문을 나누는 필수 구분선입니다.

```markdown
| 방법 | 정확도 | 지연 시간 |
| --- | ---: | ---: |
| Baseline | 80% | 100 ms |
| Proposed | 85% | 90 ms |
```

실제 표시:

| 방법 | 정확도 | 지연 시간 |
| --- | ---: | ---: |
| Baseline | 80% | 100 ms |
| Proposed | 85% | 90 ms |

위 숫자는 **표 표시를 설명하기 위한 가상 값**입니다. 실제 리뷰에는 원문에서 확인한 수치를 사용합니다. `---:`는 오른쪽 정렬, `:---:`는 가운데 정렬입니다.

## 코드 넣기

짧은 변수 이름은 백틱 하나로 감싸고, 여러 줄 코드는 백틱 세 개로 감쌉니다. 첫 줄에 `python`, `cpp`, `bash` 같은 언어 이름을 붙이면 구문 강조가 적용됩니다.

````markdown
```python
def linear(x, weight, bias):
    return weight * x + bias
```
````

실제 표시:

```python
def linear(x, weight, bias):
    return weight * x + bias
```

Markdown 문법 자체를 설명하고 싶을 때는 코드 블록을 사용합니다. 백틱 세 개가 들어 있는 예시를 감싸려면 바깥쪽을 백틱 네 개로 감싸면 됩니다.

## 논문 리뷰를 쓸 때의 추천 구성

```markdown
## 논문 정보
논문 제목, 저자, 학회·연도, 원문과 코드 링크

## 한 줄 요약
어떤 문제를 어떤 방법으로 해결했는가?

## 배경과 문제 설정
기존 연구의 한계와 이 논문의 목표

## 핵심 아이디어
방법의 원리, 수식, 구조와 기존 연구와의 차이

## 실험과 결과
데이터셋, 비교 방법, 주요 수치와 ablation

## 한계와 내 생각
검증이 부족한 부분, 의문점, 장점과 한계

## 내 연구와의 연결
활용 아이디어와 직접 해볼 후속 실험

## 참고 자료
논문 원문, 공식 코드, 관련 연구
```

논문의 주장과 내 해석을 구분하고, 직접 실험한 내용에는 환경과 실행 조건도 기록하면 나중에 다시 읽기 좋습니다.

## 저장 후 확인할 것

- 공개할 글이면 **초안으로 저장**이 꺼져 있는지 확인합니다.
- 발행일이 미래로 되어 있지 않은지 확인합니다.
- **Save** 후 자동 배포가 끝날 때까지 잠시 기다립니다.
- 실제 블로그에서 수식·이미지·표·코드와 목차를 확인합니다.
- 수정은 글 관리 화면에서 같은 글을 다시 열어 저장하면 됩니다.
